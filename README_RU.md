# SAFIA · Заявки посуды — версия для Netlify

Обновление интерфейса: 29 октября 2026, версия 2.2. Полный исходный код.

Насыщенная бежевая палитра. На моноблоках от 1000×620 вся посуда выбранной зоны размещается по 10 карточек на экране (два ряда по пять); если позиций больше — появляются страницы. Кнопка отправки закреплена в верхней части корзины, а выбранные позиции прокручиваются внутри неё. Заявки этажа открываются отдельной кнопкой рядом с заголовком каталога. На телефонах используется прокрутка для сохранения читаемости.

Проверено в браузере: 1280×720 и 1024×768 — все 10 карточек помещаются, кнопка отправки видна, комментариев нет. Корзина из всех 10 позиций также не скрывает кнопку.

## Что уже сделано

- Главная страница: выбор этажа и сразу зоны; отдельная диспетчерская.
- На рабочем экране нет бокового меню. Кнопка «Назад» возвращает к выбору.
- Зоны закреплены сверху при прокрутке списка посуды.
- Крупные кнопки, +/−, быстрый набор +5 и +10.
- 20 позиций: 10 для зала/магазина и 10 для зоны «Бар».
- Количество от 1 до 999 и срочность; поле комментария убрано.
- Общая очередь трёх этажей, назначение раннеров, отправка и отметка «Доставлено» одним нажатием.
- Таймер: по умолчанию 3 минуты — жёлтый, 5 минут — красный; пороги меняются.
- Звук новой заявки включается отдельно на каждом моноблоке.
- История этапов; последние 300 завершённых заявок отображаются в интерфейсе.
- Постоянная общая база PostgreSQL через Netlify Database.
- Повтор отправки не дублирует заявку. Одновременные изменения проверяются по версии.
- Вход без логина, пароля и кода устройства: сразу открывается выбор этажа.

## Где разместить

Рекомендуемая схема: **GitHub (код) → Netlify (сайт и серверные функции) → Netlify Database (общие заявки)**.
GitHub Pages обслуживает статические файлы: серверная часть этого архива там не работает.

## Публикация через GitHub и Netlify

1. Распакуйте архив.
2. Создайте репозиторий GitHub. Загрузите СОДЕРЖИМОЕ папки проекта в корень репозитория: там должны находиться `package.json` и `netlify.toml`. Не загружайте сам ZIP вместо файлов.
3. В Netlify выберите импорт существующего проекта из GitHub и укажите репозиторий.
4. Настройки сборки уже записаны в `netlify.toml`:
   - Build command: `npm run build`
   - Publish directory: `dist`
   - Functions directory: `netlify/functions`
   - Node.js: 22
5. Переменная `SITE_ACCESS_CODE` больше не нужна. Если она осталась в Netlify от прошлой версии, код её игнорирует; удалять её для запуска не обязательно.
6. Запустите deploy. Проект содержит пакет `@netlify/database` и миграцию в `netlify/database/migrations/`: поддерживаемый текущей платформой Netlify Database создаёт базу и применяет миграции при публикации. Если аккаунт запрашивает включить Database или принять условия тарифа, завершите этот шаг в Netlify, затем повторите deploy.
7. Откройте опубликованный адрес — выбор этажа появится сразу, без входа.
8. На трёх моноблоках выберите соответствующие этажи и зоны. На четвёртом моноблоке второго этажа откройте «Диспетчерская».
9. На диспетчерском моноблоке нажмите значок звука один раз. При необходимости включите полный экран.
10. Отправьте пробную заявку с одного устройства: она должна появиться у диспетчера примерно через 3 секунды. Назначьте раннера, отправьте посуду и отметьте «Доставлено» на этаже.

Не ограничивайтесь загрузкой папки `dist` через Netlify Drop: для этого проекта также нужны серверные функции, зависимости и база. Публикуйте репозиторий целиком.

## Важно о данных

База привязана к конкретному проекту Netlify. Все моноблоки должны открывать ОДИН И ТОТ ЖЕ опубликованный адрес. Если создать четыре отдельных сайта, базы тоже будут разными.

Этот архив запускает новую отдельную базу. Заявки существующей версии chatgpt.site автоматически не переносятся. Данные не хранятся в `localStorage`; там сохраняется только настройка звука.

В этой версии сайт открыт для всех, у кого есть ссылка: доступны заявки, диспетчерская и настройки. Логин, пароль, код устройства и отдельные роли отсутствуют.

## Структура кода

- `src/App.tsx` — все рабочие экраны.
- `src/model.ts` — каталог, зоны по умолчанию и типы данных.
- `src/app.css` — внешний вид и сенсорные кнопки.
- `src/main.tsx` — запуск приложения сразу с выбором этажа.
- `netlify/functions/api.mts` — серверные маршруты `/api/*`.
- `server/requests.ts` — проверки и этапы заявки.
- `server/database.ts` — параметризованные запросы PostgreSQL.
- `netlify/database/migrations/0001_dish_requests.sql` — структура постоянной базы.
- `netlify.toml` — настройки Netlify.

## Проверка и разработка

Нужен Node.js 22 или новее.

```sh
npm install
npm run check
npm test
npm run build
```

Для полноценного локального запуска установите актуальный Netlify CLI, свяжите проект через `netlify link` и запустите `netlify dev`. Используйте локальную базу Netlify Database и команду `netlify database migrations apply` согласно текущей документации CLI. Нужен весь серверный стек; открытие `index.html` двойным щелчком не подключает общую базу.

## Проверено перед передачей

- Сборка фронтенда и проверка TypeScript.
- Каталог из 20 позиций и разделение по зонам.
- На PostgreSQL-совместимом локальном движке: создание таблиц, отправка без дублирования, смена статуса, отказ устаревшему изменению и сохранение настроек.
- Открытый вход без кода и cookie; защита от запросов с другого сайта сохранена.

Размещение именно этого архива в вашем Netlify-аккаунте ещё не выполнялось. Облачное подключение базы необходимо проверить первым тестом между двумя моноблоками после deploy.

## Как обновить уже работающий сайт

Замените файлы в том же репозитории содержимым проекта из архива. Удалите старый `server/auth.ts`, если обновляете вручную (новый код его не использует). Опубликуйте новую версию в том же проекте Netlify. Переменная SITE_ACCESS_CODE не требуется. После публикации обновите страницу на моноблоках. База и заявки сохраняются в том же Netlify-проекте; новые миграции не добавлялись.
